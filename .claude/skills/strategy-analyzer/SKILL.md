# 策略改进分析器 (Strategy Analyzer)

此技能帮助用户深度分析 trader_center 回测系统的策略表现，通过结合策略代码、交易日志和回测结果，找出策略的问题和改进方向。

## 使用场景

当用户有以下需求时，使用此技能：
- 分析策略回测结果，找出表现不佳的原因
- 审查策略代码，寻找逻辑漏洞或改进空间
- 分析交易日志，优化入场/出场时机
- 评估参数设置，寻找最优参数组合
- 诊断策略问题（频繁交易、回撤过大、胜率低等）
- 对比多个策略版本的表现差异

## 数据来源

分析器会从以下位置读取数据：

### 1. 策略代码
- 路径：`trader_center/backtest/strategy/` 或用户自定义路径
- 必须继承 `BaseStrategy`

### 2. 回测日志
- 路径：`logs/backtest/{strategy_name}/{timestamp}_{hash}/`
- 文件清单：
  - `summary.json` - 回测摘要和绩效指标
  - `trades.csv` - 完整交易记录（含盈亏）
  - `signals.csv` - 交易信号日志（含触发条件、指标值、置信度）
  - `capitals.csv` - 每日资金状态
  - `positions.csv` - 每日持仓明细
  - `orders.csv` - 订单执行记录
  - `performance_report.html` - QuantStats 绩效报告（可选）

## 分析流程

执行策略分析时，遵循以下步骤：

### 第一步：收集信息

1. **确定策略名称和日志路径**
   - 如果用户指定了路径，直接使用
   - 否则，列出 `logs/backtest/` 下的可用策略和回测记录

2. **读取策略代码**
   - 分析策略类的 `name`、`description`、`params`
   - 理解 `__init__` 中的指标定义
   - 分析 `next()` 中的交易逻辑

3. **读取回测日志**
   - 加载 `summary.json` 获取整体绩效
   - 加载 `trades.csv` 分析交易细节
   - 加载 `signals.csv` 分析信号质量
   - 加载 `capitals.csv` 分析资金曲线
   - 加载 `positions.csv` 分析持仓管理

### 第二步：多维度分析

#### A. 代码层面分析
- **指标选择**：使用的技术指标是否合理？参数设置是否恰当？
- **信号生成**：入场/出场条件是否清晰？是否有确认机制？
- **仓位管理**：是否考虑仓位控制？是否有加仓/减仓逻辑？
- **风险管理**：是否有止损止盈？是否考虑最大回撤控制？
- **A股适配**：是否正确处理 T+1、涨跌停等限制？

#### B. 绩效层面分析
- **收益率**：绝对收益、年化收益、超额收益（相对基准）
- **风险指标**：最大回撤、波动率、夏普比率、Sortino 比率
- **交易统计**：总交易次数、胜率、盈亏比、平均持仓时间
- **收益分布**：盈利交易和亏损交易的分布特征
- **时间分布**：收益的时间集中度（是否依赖特定行情）

#### C. 信号层面分析
- **信号频率**：信号产生是否过于频繁或稀疏？
- **信号质量**：高置信度信号的实际表现如何？
- **指标背离**：信号触发时的指标值与后续走势的关系
- **假信号**：震荡市中的信号质量分析

#### D. 交易层面分析
- **入场质量**：买入后短期走势（1日、3日、5日）
- **出场时机**：卖出后是否错过继续上涨或避免下跌？
- **滑点分析**：预期价格与实际成交价格的差异
- **手续费影响**：交易成本对收益的影响

#### E. 资金管理分析
- **仓位波动**：仓位比例的变化是否合理？
- **资金利用率**：闲置资金比例是否过高？
- **回撤恢复**：最大回撤期间的应对策略

### 第三步：问题诊断

常见问题及诊断方法：

| 问题 | 诊断指标 | 分析方法 |
|------|---------|---------|
| 频繁交易 | 交易次数、持仓时间 | 检查信号过滤机制 |
| 胜率过低 | 胜率 < 40% | 分析假信号原因 |
| 盈亏比差 | 盈亏比 < 1.5 | 检查止损止盈设置 |
| 回撤过大 | 最大回撤 > 20% | 分析回撤期间的交易 |
| 收益不稳定 | 收益标准差大 | 检查策略适应性 |
| 过度拟合 | 交易次数少但收益高 | 参数敏感性测试 |

### 第四步：改进建议

针对发现的问题，提供具体改进方案：

1. **参数优化**：建议调整的参数及理由
2. **信号过滤**：添加额外的确认条件
3. **风控增强**：改进止损止盈逻辑
4. **仓位管理**：优化仓位控制策略
5. **市场环境**：添加市场状态判断

## 使用示例

### 示例 1：分析最近的一次回测

用户说："帮我分析一下刚才运行的 SMA 策略回测结果"

```
1. 找到最新的回测日志目录: logs/backtest/sma_cross/
2. 读取策略代码: trader_center/backtest/strategy/examples.py 中的 SmaCrossStrategy
3. 加载所有日志文件
4. 执行完整分析流程
5. 输出分析报告
```

### 示例 2：对比两个版本的策略

用户说："对比一下 SMA 策略修改参数前后的表现"

```
1. 列出 sma_cross 的所有历史回测记录
2. 让用户选择要对比的两个版本
3. 分别读取两个版本的策略代码（如果不同）
4. 对比分析两个版本的绩效差异
5. 输出对比报告
```

### 示例 3：诊断具体问题

用户说："为什么我的策略回撤这么大？"

```
1. 读取回测日志，重点关注 capitals.csv 和 positions.csv
2. 分析回撤期间的持仓和交易
3. 识别导致回撤的交易
4. 检查是否有止损逻辑
5. 给出具体的改进建议
```

## 注意事项

1. **数据完整性**：如果某些日志文件缺失，分析时跳过相应部分
2. **时间对齐**：确保交易记录、信号记录和资金记录的时间对齐
3. **避免过度拟合**：提醒用户区分样本内和样本外表现
4. **市场环境**：分析策略在不同市场环境下的表现差异
5. **交易成本**：确保分析中充分考虑手续费和滑点的影响
